# ECC research

Исследовательский проект для воспроизводимых экспериментов с rateless-кодами.
Общая реализация находится в `notebooks/_shared`, а сами ноутбуки оставляют
постановку эксперимента, параметры и интерпретацию результата.

## Подготовка окружения

```powershell
uv sync --group dev
uv run python -m ipykernel install --user --name ecc-research --display-name "Python (ecc-research)"
uv run jupyter lab
```

## Интерактивная лаборатория Primitive Rateless

Откройте `notebooks/y_ecc/individual_inspection.ipynb` в ядре проекта:

1. Выполните настройку и ячейку редактора. Меняйте x, N, T и редактируйте y′.
2. Выберите конфигурации в словаре `DECODERS` и запустите **Decode the current observation**.
3. Выполните ячейки метрик, отдельных битов и эволюции LLR. В каждой один Plotly-график:
   группы кнопок выбирают декодеры и метрики/биты, а для эволюции — один декодер.
   Переключение использует готовые истории и не запускает декодирование заново.

Правки в редакторе не запускают декодирование и не обновляют графики.
Один `editor.snapshot()` фиксирует наблюдение для всего сравнения. Каждый декодер
получает отдельную копию входа. `histories` — словарь «имя конфигурации → ndarray
формы (T+1, N)», а истинное слово хранится отдельно в `true`. Последующие правки
редактора не меняют завершённые расчёты.

Начальное сравнение: `avail-softmajvote(tanh)`,
`avail-softmajvote(sqrt-sign)` и `avail-softmajvote(min-sum(0.8))`.
Параметры фиксируются через `functools.partial`. Для новой архитектуры достаточно
реализовать `decode(initial_batch, terms=DEFAULT_TERMS, iterations=20, return_history=False, ...)`
в `notebooks/_shared/core/decoders` и добавить функцию в `DECODERS`.

Декодеры принимают батч `(B, N)` и возвращают финальные LLR `(B, N)`.
При `return_history=True` результат имеет форму `(B, T+1, N)`.
Индивидуальный ноутбук оборачивает наблюдение в батч размера 1.

## Восстановление информационных битов x

Ноутбук `notebooks/x_ecc/individual_inspection.ipynb` использует тот же редактор,
но восстанавливает информационные биты x. Начальные оценки x имеют случайные знаки
и малую магнитуду `INIT_LLR_SCALE`; каждый метод получает одну и ту же инициализацию.
Декодер `avail-softmajvote` передаёт от каждой колонки G сообщения участвующим
битам x: soft-XOR фиксированного LLR наблюдения y′ и остальных битов колонки.
Все сообщения вычисляются по предыдущей итерации и прибавляются к оценкам x.
G хранится как списки связей, без плотной матрицы. Графики показывают K оценок x.

## Сравнение на случайных шумовых входах

`notebooks/y_ecc/marginal_comparison.ipynb`: K=16, N=32, 1024 батча по 128 примеров.
Для каждого примера независимо выбираются x и SNR из `(-3, 3)` дБ.
SNR определяется как Es/N0 при Es=1: `sigma² = 1 / (2 * 10**(SNR_dB/10))`,
а вход декодера — `2 * received / sigma²`.

Joblib запускает по задаче на батч, tqdm показывает завершённые батчи.
Все методы получают одинаковые наблюдения. Numba прогревается до замеров.
Анализ показывает нс/пример и условные распределения SER по SNR:
среднее и двумерную гистограмму SER, нормализованную по каждому столбцу SNR.
Истории в этом эксперименте не выделяются.

Декодеры не получают истинное слово, не вычисляют метрики и не строят графики.
`_shared.application.metrics.metrics(history, true, terms=...)` возвращает численные метрики.
`_shared.presentation.plots.metrics(history, true, terms=...)`, `bits(history, true)` и
`evolution(history, true)` строят отдельные графики; `plots.compare(histories, true, kind=...)`
объединяет их в один график с независимыми селекторами. Полином нужен анализу только
для доли нарушенных проверок. Цвет линии обозначает метрику или бит, тип линии — декодер.

Полином задаётся списком ненулевых степеней `P`, по умолчанию `(0, 2, 5)`.
K вычисляется из P. Примитивность принимается на доверии; A и G не создаются.
Кодирование использует разреженную рекуррентность LFSR и работает также при K=32
и K>64. Для наличия проверок выбирайте N>K.

В `notebooks/_shared` находятся LFSR, синхронные итерации soft-XOR, метрики,
редактор anywidget и функции построения Plotly. Численные циклы ускорены через
`numba.njit(cache=True)`; первый вызов может включать компиляцию. История каждого
декодера занимает `8 * (T + 1) * N` байт, не считая графиков и их копий данных. Документация
внутри ноутбука — на английском.
